# Decbricks — 09: Programmatic SEO Evaluation

> Skill: programmatic-seo. Default for a studio of this size: **no**. Documented so the decision
> has a rationale and a re-entry condition.

## Verdict: not now

A templated page set would serve real searches only with real data behind each page. Decbricks
today has: four indexable pages, no GSC baseline, and exactly one differentiated dataset —
**its own campaign execution** (Findtern, Upcoming Engineers, DevSummit, DSC SRM) plus 53
documented capabilities across 7 services.

## Patterns evaluated and rejected (for now)

| Pattern | Why rejected today |
|---|---|
| Locations ("software development company in <city>") ×50 Indian cities | No real local operations per city; near-duplicate pages = doorway risk; the only real location is Chennai |
| Personas ("software development for <industry>") ×N | No per-industry evidence or vocabulary; would be template-swap thin content |
| Comparisons ("X vs Y") | Requires honest per-competitor facts and risk of false claims; none sourced |
| Capabilities ("what is <capability>") ×53 | Glossary intent, high competition, no proprietary angle; low value per page |
| Templates/examples galleries | No template product exists |

## What would change the answer (re-entry conditions)

1. **A real proprietary dataset** — e.g. verifiable outreach/campaign benchmarks (volumes, reply
   rates by segment) the owner consents to publish. That unlocks a maintained statistics page
   (strongest link-earning format) before any templated set.
2. **GSC evidence** that impression volume concentrates on one pattern (say, "AI agent
   development services" modifiers) beyond what a single service page covers.
3. **Delivery capacity** — a repeatable, per-page meaningful assembly process with a human editor,
   not variable-swapping (the thin-content failure mode).

Until then, the 03/04 architecture (hub + up to 3 hand-built service pages + case studies) is the
correct scope.
